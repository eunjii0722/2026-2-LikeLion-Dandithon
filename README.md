# 내 사과나무 1년 🌳

> **2026 단디톤 프로젝트**  
> 경북의 사과나무 한 그루를 분양받고, 사진과 AI 성장일기·편지를 통해 계절의 변화를 함께 경험하는 서비스입니다.

- **배포 사이트:** https://my-apple-year.vercel.app/
- **GitHub:** https://github.com/eunjii0722/2026-2-LikeLion-Dandithon
- **개발 환경:** Next.js 16 (App Router), React 19, JavaScript, Gemini API, OpenAI API, 기상청 ASOS API, Vercel

> **프로젝트 성격:** 해커톤용 프로토타입입니다. 분양 결제와 배송은 실제로 처리되지 않으며, 준비된 성장 기록·편지는 시연용 예시입니다. 실제 농가와 연동된 상용 서비스가 아닙니다.

## 1. 서비스 이용 방법

사이트에 처음 접속하면 두 가지 경로 중 하나를 선택할 수 있습니다.

| 시작 방법 | 목적 | 처음 표시되는 기록 |
| --- | --- | --- |
| **나무 고르러 가기** | 처음 분양받는 사용자 경험 확인 | 성장일기 0편, 편지 0통, 함께한 기간 **0주차** |
| **홍이의 성장 기록 둘러보기** | 이미 기록이 쌓인 서비스 체험 | 성장일기 **4편**, 편지 **7통**, 생육 **39주차** |

### A. 처음 분양받기

1. [배포 사이트](https://my-apple-year.vercel.app/)에 접속합니다.
2. **나무 고르러 가기** → 홍이 프로필 → **이 나무 분양받기**로 이동합니다.
3. 분양 신청 화면에서 **결제하고 분양받기 (시연)**를 누릅니다. **실제 결제는 발생하지 않습니다.**
4. 홈에서 홍이와 함께한 기간 **0주차**를 확인합니다.
5. **편지 쓰기**, **나무에게 묻기**, **타임라인**, **일기**, **앨범**을 둘러볼 수 있습니다.

분양 후 화면의 **생육 주차**와 **함께한 기간**은 서로 다릅니다.

- **생육 주차:** 나무의 성장 달력에서 몇 주차인지 나타내는 값입니다. 일반 신규 사용자는 현재 구현상 생육 14주차부터 시작합니다.
- **함께한 기간:** 사용자가 분양받은 뒤 경과한 기간입니다. 분양 직후에는 0주차입니다.

> 신규 사용자에게 시연용 과거 일기와 편지는 자동 표시되지 않습니다. 이번 주 새 사진이 등록되지 않았다면 사진 미등록 안내가 표시됩니다.

### B. 홍이의 성장 기록 둘러보기 (추천 시연 경로)

1. **저장된 기록이 없는 브라우저 프로필**에서 배포 사이트에 접속합니다.
F12를 눌러 개발자 도구 -> Application(애플리케이션) 탭 -> 기존 데이터 삭제
2. 홈에서 **홍이의 성장 기록 둘러보기**를 누릅니다.
3. 준비된 성장 기록을 불러오면 홈이 갱신됩니다.
4. 다음 순서로 체험해 보세요.

   - **홈:** 홍이의 현재 생육 39주차와 최근 35주차 성장일기 확인
   - **타임라인:** 봄부터 여름까지 성장 기록 열어 보기
   - **일기:** 사투리 표현을 누르고 의미 확인, **이 일기의 근거** 펼치기
   - **편지:** 과거 편지 7통과 일기 답장 연결 확인
   - **단어장:** 일기에서 배운 사투리 표현 확인 (`/words`)
   - **나무에게 묻기:** 과거 성장일기를 바탕으로 홍이와 AI 대화

**시연 데이터 구성**

| 계절 | 주차 | 표시 단계 | 상태 |
| --- | --- | --- | --- |
| 봄 | 18주차 | 개화 | 준비된 일기 |
| 봄 | 21주차 | 착과 | 준비된 일기 |
| 여름 | 28주차 | 비대 | 준비된 일기 |
| 여름 | 35주차 | 착색 | 준비된 일기 |
| 가을 | 39주차 | 수확 직전 | **생성 전에는 일기 없음** |
| 가을 | 41주차 | 수확 예정 | 잠금 상태 |

- 둘러보기에서는 **생육 39주차**, **함께한 기간 25주차**로 설정됩니다.
- 39주차의 **수확 직전**은 시기 표현입니다. 라이브 사진 분석 결과가 반드시 `수확기`로 나오는 것은 아닙니다.

### C. 기존 기록이 있어 둘러보기가 실행되지 않을 때

시연 초기화는 **기존 사용자 데이터를 덮어쓰지 않도록** 만들어졌습니다. 이미 분양했거나 편지·대화 등을 저장한 브라우저라면 둘러보기 기능을 실행할 수 없습니다.

- **권장:** 새 크롬 프로필 또는 새 시크릿 창에서 사이트를 열어 둘러보기를 실행하세요.
- 다른 시크릿 창이 이미 열려 있으면 해당 시크릿 세션의 저장소를 공유할 수 있습니다.
- 기존 기록을 보존하고 싶다면 사이트 저장소를 삭제하지 마세요.

개발·발표용으로는 기존 콘솔 명령도 사용할 수 있습니다. **저장 데이터가 없는 사이트 탭**에서 `F12 → Console`을 열고 실행하세요.

```javascript
const { initializeDemo } = await import("/demo/initialize.js");
await initializeDemo();
```

결과의 `ok: true`를 확인하면 됩니다. **일반 방문자는 콘솔을 사용할 필요가 없습니다.**

## 2. 농부 화면에서 AI 성장일기 만들기

**농부 화면:** https://my-apple-year.vercel.app/farmer

현재 농부 화면은 해커톤 시연용이며, 실제 농가 운영자 인증·권한 관리 기능은 구현되지 않았습니다.

### 39주차 라이브 시연 순서

먼저 **홍이의 성장 기록 둘러보기**를 실행한 브라우저에서 진행하는 것을 권장합니다.

1. `/farmer`에 접속합니다.
2. **이번 주 사진**에 사과나무 사진을 업로드합니다.
   - 저장소의 예시 사진: `public/images/demo/autumn-demo.jpg`
   - 사진이 여러 나무를 포함한다면 **과수원 공통**, 개별 나무를 특정할 수 있다면 **내 나무**를 선택합니다.
3. **생육 주차:** `39주차`를 선택합니다.
4. **관찰 날짜:** 시연 예시로 `2026-09-26`을 선택할 수 있습니다.
5. 필요하면 **농부 메모**를 입력합니다. 실제 확인하지 않은 내용을 확인했다고 주장하지 말고, **농부가 직접 확인함** 체크박스도 실제 확인한 경우에만 선택합니다.
6. **분석하기**를 눌러 Gemini Vision 결과를 확인합니다.
   - 생육 단계, 확신도, 꽃·열매 관찰, 색상, 관찰 내용 및 불확실한 점이 표시됩니다.
7. 날씨 조회 상태를 확인한 후 **이번 주 일기 만들기**를 누릅니다.
8. 일기 제목·본문과 **일기를 저장했어요** 안내를 확인합니다.
9. **홈 → 타임라인 → 39주차 일기**에서 새 기록이 표시되는지 확인합니다. 새로고침 후에도 유지되는지 확인해 보세요.

**API 동작 관련 주의사항**

- Vision·Diary는 실제 Gemini API를 호출하므로 응답 시간과 결과는 매번 달라질 수 있습니다.
- 날씨는 기상청 ASOS 관측자료를 조회합니다. 일부 날짜는 기온·강수량이 누락되거나 아직 제공되지 않을 수 있습니다. **없는 자료를 임의로 0으로 채우지 않습니다.**
- `2026-09-26`은 시연용 관찰 날짜입니다. 사진의 실제 촬영일이나 농부가 현장에서 확인한 날짜라고 주장하면 안 됩니다.
- 사진 분석 결과가 `착색`으로 나오더라도, 화면의 `수확 직전`은 39주차의 계획상 시기 표현일 수 있습니다. **AI 원본 판정과 화면 표시를 구분**합니다.
- 생성된 일기와 사진은 현재 브라우저 저장소(localStorage)에 저장됩니다. 다른 기기나 브라우저와 자동 동기화되지 않습니다.

## 3. 주요 화면 및 기능

| 경로 | 기능 |
| --- | --- |
| `/` | 홈, 신규 분양 또는 성장 기록 둘러보기 |
| `/trees` | 나무 목록 |
| `/trees/tree-1` | 홍이 소개 및 분양 이동 |
| `/trees/tree-1/adopt` | 가상 분양 신청 |
| `/timeline` | 계절별 생육 타임라인 |
| `/diary/39` | 해당 주차 일기 또는 미생성 안내 |
| `/letter` | 홍이에게 편지 보내기 및 편지 이력 |
| `/chat` | 성장일기와 기상청 관측자료를 근거로 한 OpenAI 대화 |
| `/words` | 저장한 사투리 단어장 |
| `/harvest` | 수확 앨범 및 수확 예정 정보 |
| `/farmer` | 사진 분석·일기 생성용 농부 화면 |

**서버 API**

| 엔드포인트 | 메서드 | 역할 |
| --- | --- | --- |
| `/api/vision` | `POST` | 업로드한 사진을 Gemini로 분석 |
| `/api/diary` | `POST` | 분석 근거·관찰 날짜·날씨·편지를 바탕으로 성장일기 생성 |
| `/api/chat` | `POST` | 최근 성장일기 또는 청송 ASOS 관측자료를 바탕으로 홍이의 답변 생성 |
| `/api/weather?date=YYYY-MM-DD&treeId=tree-1` | `GET` | 해당 날짜의 기상청 ASOS 일자료 조회 |

> API 주소를 브라우저 주소창에 여는 것만으로 `POST` 기능을 테스트할 수는 없습니다. 화면에서 버튼을 누른 뒤 `F12 → Network → Fetch/XHR`에서 각 요청의 상태 코드와 응답 내용을 확인하세요. `200 OK`는 해당 요청이 성공했다는 뜻이지 모든 사진에서 정확한 판단을 보장하는 것은 아닙니다.

## 4. 로컬 개발 환경 설정

### 준비물

- Git
- Node.js **20.9 이상** (LTS 권장)
- npm
- VS Code 등 코드 편집기

### 저장소 받기

```powershell
git clone https://github.com/eunjii0722/2026-2-LikeLion-Dandithon.git
cd 2026-2-LikeLion-Dandithon
npm ci
```

이미 저장소가 있다면 다시 clone하지 말고, 먼저 변경 사항을 확인한 뒤 최신 `main`을 가져옵니다.

```powershell
git status
git switch main
git pull --ff-only origin main
npm ci
```

> 커밋하지 않은 작업이 있으면 먼저 보존하세요. `git switch`나 `git pull`이 실패할 수 있으며, 변경 파일을 임의로 삭제하면 안 됩니다.

### API 키 설정

프로젝트 루트에 개인 설정 파일을 만듭니다.

```powershell
Copy-Item .env.example .env.local
```

`.env.local`에 각자 발급받은 키를 입력합니다.

```dotenv
GEMINI_API_KEY=여기에_Gemini_API_키
KMA_ASOS_SERVICE_KEY=여기에_기상청_ASOS_인증키
OPENAI_API_KEY=여기에_OpenAI_API_키
```

- **Gemini:** 사진 분석과 AI 성장일기에 필요합니다.
- **OpenAI:** 홍이 AI 대화에 필요합니다. 키는 서버에서만 사용합니다. 저비용 `gpt-5-nano`를 사용하며, 모델 종료 공지에 맞춰 교체해야 합니다.
- **기상청:** [공공데이터포털 지상(종관, ASOS) 일자료 조회서비스](https://www.data.go.kr/data/15059093/openapi.do) 인증키를 사용합니다.
- 키가 없으면 해당 외부 API 기능이 제한될 수 있지만 기본 프론트엔드 화면은 확인할 수 있습니다.
- `.env.local`은 **절대 GitHub에 올리지 마세요.** API 키를 소스 코드에 직접 쓰거나 `NEXT_PUBLIC_` 환경변수에 넣지 않습니다.

### 개발 서버 실행

```powershell
npm run dev
```

- 접속: http://localhost:3000
- 종료: 터미널에서 `Ctrl + C`
- `.env.local`을 수정했다면 개발 서버를 재시작합니다.

### 프로덕션 모드로 로컬 확인

```powershell
npm run build
npm start
```

**배포 환경(Vercel)**에서도 별도로 `GEMINI_API_KEY`, `KMA_ASOS_SERVICE_KEY`, `OPENAI_API_KEY`를 Environment Variables에 등록해야 합니다. 로컬 `.env.local`이 배포 서버에 자동 복사되지는 않습니다. 키를 변경하면 새 배포에 반영됐는지 확인하세요.

## 5. 테스트 및 문제 해결

### 기본 테스트

```powershell
npm run lint
npm run build
node --test
```

마지막 확인 시점의 작업 보고에서는 **자동 테스트 150개가 통과**했습니다. 이후 코드 변경에 따라 테스트 개수는 달라질 수 있습니다.

### 자주 발생하는 상황

| 증상 | 확인할 사항 |
| --- | --- |
| 둘러보기 실행이 거부됨 | 기존 `localStorage` 기록이 있는지 확인하고 **빈 브라우저 프로필**에서 재시도 |
| 새로 분양했는데 과거 일기가 없음 | **정상 동작**: 신규 분양은 성장 기록 0편부터 시작 |
| 39주차 일기가 없음 | **정상 초기 상태**: 농부 화면에서 새 일기를 생성해야 함 |
| Chat 응답이 늦음 | OpenAI 응답 지연 가능. `F12 → Network`에서 `/api/chat`의 상태·시간 확인 |
| Chat에서 AI 결제 잔액 오류 | Vercel 또는 로컬의 `OPENAI_API_KEY`가 속한 프로젝트의 사용 한도·결제 상태 확인 |
| Vision·Diary가 실패함 | Vercel 또는 로컬의 `GEMINI_API_KEY`, 요청 오류 메시지, 서버 로그 확인 |
| 날씨에 '관측자료 없음' 표시 | 인증키 누락·날짜 미제공·관측값 누락 가능. `/api/weather` 응답의 `reason` 확인 |
| 39주차 사진이 없다고 표시됨 | 해당 주차 일기 생성 전이면 정상. 35주차 사진은 아래 최근 일기에서 확인 |
| 배포 후 예전 시연 데이터가 보임 | 저장소는 브라우저별로 유지됨. **별도 빈 프로필**에서 최신 시연 기록 초기화 |

Chrome에서 `F12 → Network → Fetch/XHR`를 열면 다음 요청을 확인할 수 있습니다.

- `POST /api/chat`: `answer`와 필요 시 `source` 확인
- `POST /api/vision`: `growth_stage`, `confidence` 확인
- `POST /api/diary`: `title`, `text`, `evidence` 확인
- `GET /api/weather`: `weather`, `reason` 확인 (`200 OK`인데도 `weather: null`일 수 있음)

## 6. 협업 및 GitHub 작업 규칙

1. 작업 전 `git status`로 변경 파일을 확인합니다.
2. 최신 `main`에서 기능별 브랜치를 만들어 작업합니다.
3. 수정한 파일만 선택해 스테이징하고, 변경 사항을 확인한 뒤 커밋합니다.
4. 원격 브랜치에 푸시하고 Pull Request를 생성합니다.
5. 리뷰 후 `main`에 머지합니다.
6. Vercel의 최신 프로덕션 배포가 성공했는지 확인합니다.

```powershell
git switch main
git pull --ff-only origin main
git switch -c FE/feature/기능명

# 기능 구현 후, 실제 수정한 파일만 추가
git status
git add -- components/수정한파일.js
git diff --cached --check
git diff --cached --stat
git commit -m "feat: 기능 설명"
git push -u origin FE/feature/기능명
```

브랜치 예시:

- 프론트엔드: `FE/feature/기능명`
- 백엔드·AI: `BE/feature/기능명`
- 문서: `docs/기능명`

**업로드 금지:** `.env.local`, 개인 API 키, 비밀번호, `node_modules/`, `.next/`, 임시 로그 및 개인 정보가 포함된 테스트 데이터. `git add -A`를 무조건 실행하지 말고 스테이징 내용을 확인하세요.

## 7. 구현 범위와 한계

- **실제 AI API 연동:** Vision·Diary는 Gemini, Chat은 OpenAI를 호출합니다. Chat 전환은 로컬에서 실제 API로 검증했으며 프로덕션 배포 반영 여부는 별도로 확인해야 합니다. 모델 응답·속도·품질은 호출 상황에 따라 달라질 수 있습니다.
- **기상청 관측자료:** 청송군 ASOS 관측지점 데이터를 사용합니다. 데이터가 없으면 없는 것으로 표시합니다.
- **데이터 저장:** 개인별 기록은 현재 브라우저의 `localStorage`에 저장됩니다. 계정·DB·다른 기기와의 동기화 기능은 없습니다.
- **시연용 데이터:** 과거 사진과 편지·분양 시점은 예시입니다. 일부 일기는 실제 API 응답에 게시용 문구와 표시 단계 보정이 적용되었습니다. 원본 분석 기록은 별도로 보존합니다.
- **나무 정보:** 현재 홍이의 품종·농원명에는 플레이스홀더가 남아 있습니다. 실제 특정 농가의 분양 상품이라고 해석하면 안 됩니다.
- **결제·배송:** 화면상 흐름만 구현되어 있으며 실제 결제·배송은 발생하지 않습니다.
- **농부 화면:** 시연을 위한 공개 경로이며, 운영 서비스에 필요한 인증·권한 관리 기능은 없습니다.
