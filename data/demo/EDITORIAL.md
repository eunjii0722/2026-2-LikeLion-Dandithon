## 원본과 게시본

prepare-demo.mjs는 같은 합성 함수를 사용한다. 새 원본 응답이 생겨 해시가 달라지면 기존 교정을 무조건 적용하지 않고 중단한다. 교정은 실제 근거를 다시 검토한 뒤 연결해야 한다. 테스트는 임시 프로젝트에서 fetch를 차단하고 재실행하여 게시본·편지 이력·원본이 유지되는지 확인한다.

## Chat 및 Diary
Chat은 1인칭 사과나무, 보통 1~3문장 반말을 사용하도록 지시한다. 프런트가 보내는 recentDiaries는 id/treeId/week/title/text이고 서버가 모델에 전달하는 값은 id/week/title/text다. evidence.weather·원본 사진·실시간 날씨를 알고 있다고 가정하지 않는다. 근거 없는 답은 sourceId=null, 있는 답은 실제 전달된 ID만 허용하는 기존 서버 검사를 유지했다.

Diary는 4~6문장과 기존 JSON 스키마, 날씨 null·관측 수치·편지 구분·인젝션 방어를 유지한다. 과수원 범위와 내 모습 식별 불가를 자연스럽게 밝히도록 하고 고정된 두 문구 삽입은 요구하지 않는다. lib/diary-narrative.js는 과수원 범위 표현과 미확인 농부의 확인 주장을 검사한다. 이 정규식 검사는 보수적인 보조 검사이며 모든 한국어 의미·환각을 판별하는 기능은 아니다. 의미가 같은 다른 문장을 거절할 수 있고 모든 허위 주장을 찾아낸다고 보장하지 않는다. 출력 형식·문장 수·단어장 검사는 그대로다.

모델·SDK 설정·API 스키마는 바꾸지 않았다. 새 프롬프트는 이후 생성 요청부터 적용된다. 이미 localStorage에 저장된 Chat 답변과 생성 일기는 원문을 유지한다. 시연 초기화 chatHistory는 기존처럼 빈 배열이다. 기존 대화 교정은 향후 원문 백업과 명시적 사용자 승인 절차가 필요하며 이번에 구현하지 않는다.

## 내비게이션
일기 헤더는 방문 이력과 관계없이 /timeline을 가리키는 Link이며 접근성 이름은 타임라인으로 돌아가기다. router.back()은 제거했다. missing/future 상태는 지난 일반 일기가 있을 때 primary 지난 일기 보기, 그 아래 secondary 타임라인 보기를 표시한다. 이전 일기가 없으면 타임라인만 표시하고 no-tree는 나무 선택을 유지한다. Chat 뒤로가기는 변경하지 않았다.

## 실제 모델 검증 계획
이번 작업은 추가 API 호출 없이 검증한다. 승인 후 소수 요청으로 다음을 별도 확인할 수 있다.
- Chat: 근거 있는 생육 질문, 근거 없는 건강·실시간 날씨 질문, 인젝션 문구를 포함한 질문. 1~3문장 반말, 실제 ID/null, 사실 범위를 점검한다.
- Diary: orchard/tree, 낮은 확신도, null 날씨, 편지 있음/없음. 4~6문장 반말과 자연스러운 관찰 범위, 미확인 농부 주장 금지, 단어장 정합성을 점검한다.
실제 호출 결과를 보기 전에는 말투 품질이 모델에서도 통과했다고 주장하지 않는다.

## 사용자 기록 분리 후 조회 방식

게시본과 원본 검증은 그대로 유지한다. 일반 사용자에게 정적 게시본을 자동으로 합치지 않으며, 명시적 initializeDemo 실행이 게시본 네 편을 generatedDiaries에 복사한다. 초기화 시점 39주차는 별도 dandithon.demoState로 보존한다. 일기 없는 화면의 전용 stateActions만 두 버튼 가로 배치로 바꿨다. 과거의 세로 배치 설명은 이전 작업 기록이다.
